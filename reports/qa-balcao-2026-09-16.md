## Follow-up correction — 2026-09-16

### Root causes and corrections

- `PICKUP` already had the correct local validation path
  (`hasPickupRecipient` → `hasValidRecipientIdentity`), but the component suite
  did not assert that a controlled phone input remained visible after the
  parent state changed. A DOM regression test now covers the masked value.
- `counterPrintedRows` used only the pickup name for `Chamar por`; it now
  includes the masked phone when present, with a focused utility regression.
- `CounterAddressSearchService` previously sent only `street`. The BFF
  accepts optional `city` and `state`, and `AddressSearchService` forwards that
  context to the geocoder. The app now sends the authoritative unit `state`
  in the query key and request; it intentionally does not force one city, so
  configured delivery cities remain eligible.
- The cart store regression expected the pre-`lineId`/`modifiers` shape; the
  expectation now matches the current cart contract.
